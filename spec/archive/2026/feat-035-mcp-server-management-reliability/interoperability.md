# MCP 互操作设计

**状态**：本地互操作已验证；供应方真实账号及 Windows 待验收
**更新日期**：2026-09-11
**职责归属**：`talos-mcp` 负责协议行为，现有 Plugin 生命周期负责服务定义
**主方案**：[MCP Server 管理与可靠性设计](design.md)

本文定义第三方 MCP 的接入契约和可验证的兼容性范围。执行阶段与状态统一记录在[仓库根目录实施计划](../../../IMPLEMENTATION_PLAN.md)。

## 本期范围

本期支持本地、Desktop 和本地 Web 的单实例使用，通过 stdio、Streamable HTTP、Token/API Key 和本地 OAuth 接入第三方服务。Cloud 多用户与托管授权回调属于后续版本。

## 架构与持久化

第三方服务无需提供 Talos manifest。表单输入和支持的 JSON 配置导入统一生成 `McpServerDefinition`，通过 `PluginInstallTarget::ManualMcpServer` 安装。Plugin 安装流程生成 `talos-mcp.json`，复用现有事务、启用/禁用、替换和卸载语义。

服务定义、安装状态、凭据绑定、运行状态和模型可见工具目录分别归属于明确边界：

| 关注点 | 职责归属与边界 |
| --- | --- |
| 服务定义与安装 | Plugin 生命周期，不持有进程或 OAuth 会话句柄 |
| 凭据授权与绑定 | 应用/Service 层，按实例内服务定义绑定凭据，沿用已有访问检查 |
| 协议与进程执行 | `talos-mcp`，SDK 类型保持私有，凭据作为显式输入 |
| 工具发现与执行策略 | 现有工具注册表、路由及权限基础设施 |
| 登录与操作展示 | 共享 SDK 及 Web/Desktop/TUI 用户操作展示链路 |

`npx`、`uvx`、Docker 和直接可执行文件统一使用 stdio 的命令及参数定义。所需可执行文件由部署环境提供。界面必须说明实际执行的后端主机，文件系统和浏览器可用性均以该主机为准。安装成功只表示定义已持久化，不表示已经安装软件包依赖或浏览器。

## 协议与依赖目标

选定依赖基线为正式发布的 `rmcp 3.2.0`，发布日期为 2026-08-31，最低要求 Rust 1.88；发布信息核实于 2026-09-07。实施时核对固定版本的 API 与编译器兼容性。工作区依赖与 `Cargo.lock` 同步更新，检查解析后的间接依赖和所有直接调用方，包括测试 MCP server。

目标规范为 MCP `2026-07-28`。通过 SDK 支持的协商，保留与 `2025-11-25`、`2025-06-18`、`2025-03-26` 及适用的 `2024-11-05` stdio 服务的互操作能力。版本不匹配必须可观察。兼容旧协议版本不等于实现旧版 HTTP+SSE 传输。

连接入口统一使用 SDK `Auto`，以 `2026-07-28` 为发现目标、`2025-11-25` 为旧初始化请求版本；不在客户端元信息中重复保存协议选择。旧初始化响应仍需在 Talos 边界校验 SDK 已知版本，因为 SDK 的该路径不做此校验。工具目录更新分别消费新版本订阅和旧版本通知，不建立第二套协议实现。

导入的 `http` / `streamable_http` 在入口归一化；manifest 使用同一反序列化变体及别名。现有静态 bearer 输入适配属于配置契约，与协议版本回退分别处理。错误版本、取消、无效内容等负向场景验证当前行为，不以“已经删除的字段或内部函数不存在”为测试目标。

新规范包含服务发现、请求元数据、HTTP 路由、订阅和多轮往返结果的变化。SDK 负责服务发现与旧版初始化的选择、支持版本协商、元数据、路由头、响应解码和传输取消。Talos 使用 SDK 所支持的有状态或无状态 HTTP 行为。降级只能来自 SDK 明确定义的协议协商，不能通过吞掉鉴权或任意连接错误实现。

就绪状态由 Talos 定义：必要发现流程完成，并在声明工具能力时完成工具目录读取后进入就绪。仅提供资源的服务允许以空工具目录就绪。SDK 会话保持在协议边界内部，远程 HTTP 连接使用自身的生命周期。HTTP 头和鉴权必须应用到真实传输构造中，不能只保存在定义里。

## 配置导入

首期一次添加一个服务，支持表单、单个 server 对象，以及只包含一个服务的常见 `{"mcpServers": {"name": {...}}}` 片段。支持 command、args、env、cwd、HTTP URL 和 headers 等字段；鉴权输入按下文规则处理。省略传输类型时，只有 command 与 URL 恰好出现一个才允许推断。

后端同一入口校验后生成 `McpServerDefinition`，直接复用 Plugin 安装流程。前端展示后端校验后的安全字段。

名称沿用现有 MCP 校验规则，允许已有规则中的大小写，不静默改名或覆盖。每份输入最多 256 KiB。多个服务、VS Code 专属配置方言、`inputs`、变量展开、工具过滤及其他影响行为但尚未支持的字段，均明确拒绝并指出限制；不能只取第一项或静默丢字段。

导入是一次性显式操作，命令按参数数组执行。已知鉴权字段的秘密转入服务凭据；用户可将 env/header 值明确标为秘密。对无法安全解释的鉴权表达式直接拒绝。输入和错误不回显秘密；安装后的 manifest 是托管定义的事实来源。

## 鉴权与授权

鉴权方式使用带标签的强类型枚举表达：无鉴权、bearer 凭据引用、自定义头凭据引用或 OAuth 配置。非敏感字面量头部继续支持；秘密环境值按显式服务凭据绑定注入。手动、市场和静态输入在组装边界转为同一套运行规范对象，来源格式保持各自的读取职责。

HTTP 头名按大小写不敏感规则校验重复项；协议版本和路由保留头由 SDK 管理。`Authorization` 由选定鉴权方式生成，不允许与字面量头重复注入。自定义凭据头与其他头部绑定冲突时同样显式拒绝。URL 和头部验证沿用现有安全边界，错误不能回显秘密。

凭据与 manifest 分开保存。绑定包含强类型定义引用（Plugin 安装 ID 或静态配置服务名称）、适用的授权签发方/资源，以及不透明的凭据引用。本期每个服务定义维护一套生效凭据。Plugin 服务按安装 ID 绑定，静态服务按当前配置中的唯一名称绑定。删除静态定义后，通过与卸载相同的授权清理边界使相关绑定失效。OAuth 存储还保存过期和刷新状态、客户端密钥、回调地址与 SDK 选定的 resource；重连复核 issuer/resource，普通刷新保持凭据引用不变。解析后的 token 不得写入插件元数据、导出 manifest、返回客户端的运行时描述符、日志、事件或模型上下文。现有 `EnvSecretStore` 只处理 Talos 专属键，不能直接当成通用环境凭据或 OAuth 存储。

凭据持久化先核对 SDK 授权存储接口及项目现有私有文件、统一路径和原子写入设施。本地私有凭据记录负责 MCP 凭据及刷新状态的持久化。若必须新增持久化实现，放在应用层 MCP 鉴权职责内；协议运行时只接收解析后的鉴权输入。具体 SDK 接口在实施前核实，协议授权操作使用 SDK 实现。

服务凭据的设置、替换和清除通过同一服务设置路径完成，查询仅返回存在性与安全状态。首次安装涉及凭据与 manifest 时，先写入尚未绑定的私有凭据，再提交引用它的 Plugin 安装；提交失败清理临时凭据。恢复依据安装状态和凭据绑定确认是否清理，不能只凭文件名删除。替换采用新引用成功提交后清理旧引用的顺序。复用现有事务和原子写入设施。替换时只有鉴权目标和方式不变才可保留有效绑定；HTTP 端点、目标资源或鉴权方式实质变化时必须显式重新绑定，不能自动向新目标发送旧凭据。

### 连接与凭据归属

连接以静态配置服务名称或 Plugin 安装身份标识。工具发现、执行和快照共同使用该连接，当前实例工具注册表提供一致的工具投影。服务名称在实例内唯一。

服务操作沿用已有身份认证与访问检查。注销鉴权清除该服务凭据并停止关联调用；卸载或删除静态定义时清理绑定，其他服务不受影响。切换账号通过断开并重新授权完成。

### OAuth 生命周期

使用选定 SDK 的授权实现处理元数据发现、PKCE/state 校验、resource/audience 绑定、issuer 校验、token 交换和刷新。按供应方要求支持预注册客户端配置，不能假设所有服务都支持动态注册。新规范的客户端元数据能力与旧版协商，以已核实 SDK 版本的实际实现为准。

应用层负责登录编排与回调。Desktop 和本地 Web 使用与本地 Talos 后端协调的浏览器授权及回调，回调绑定发起的授权尝试。复用现有认证及用户操作设施，不把工具响应当成授权指令。访问 token 和刷新 token 均保留在服务端。凭据刷新按绑定协调，避免并发请求竞争 token 轮换。断开、卸载、替换账号或定义时使旧授权尝试和刷新失效；写回前核对绑定代次，旧回调或在途刷新不得恢复已清除的凭据或重新建立连接。授权任务通过绑定代次和取消机制控制写回。

服务设置、认证启动/状态/断开、运行时列表使用共享强类型 Request/Response。由服务设置和认证操作承载。具体方法名与生成 schema 在对应实施阶段、公开 API 前确定。所有操作引用实例内的强类型定义身份，并沿用已有调用入口权限检查。凭据设置只写；查询只返回存在性、状态和安全元数据。认证启动仅向发起客户端返回有有效期的尝试 ID 和已授权登录 URL；回调归属该次尝试。过期尝试必须清理且不能重放。

认证状态包括未认证、授权中、已认证、已过期，以及携带结构化 `ApiError` 的失败。启用/禁用不能代替登录/退出。断开会移除本地凭据并停止相关调用，清理失败单独报告。本期断开仅清除本地绑定，不执行上游授权撤销；删除本地 token 不等于撤销上游授权。导出排除凭据，卸载清除绑定且不遗留孤立秘密值。

只有完成 OAuth 才能宣称通过主流托管服务验收。仅支持 Token 的版本可以按较窄范围发布，但不能标记为完成本文全部目标。

## 能力范围与工具行为

| 能力 | 目标行为 |
| --- | --- |
| stdio 与 Streamable HTTP | 必须支持，并验证新规范及协商后的旧版行为 |
| 工具 | 有上限的完整发现、输入 schema 保留、调用、取消和结构化结果 |
| 资源与模板 | 复用已有列表/读取入口，按需分页，不在启动时预取 |
| 工具列表变化 | 通过协商后的 SDK 通知/订阅，只刷新受影响连接的目录 |
| 交互式输入 | 本期不实现；补充输入结果返回明确不支持错误，不作为空成功结果 |
| Prompts | 不属于首期执行范围，不宣称完整支持 |
| Sampling、MCP Apps、任务扩展 | 暂缓；宿主端到端行为完整前明确不支持 |
| 旧版双端点 HTTP+SSE | 不支持；说明传输限制，不静默尝试其他端点 |

不能因为 `rmcp` 定义了某能力的类型，就宣告客户端支持该能力。新多轮往返结果必须穷尽处理：要求补充输入的响应不是成功的空工具结果。交互功能实现前，返回明确、安全的不支持能力错误，并且不宣告该能力。兼容性测试要区分普通新规范调用与可选交互调用。

工具发现沿游标读取完整目录，最多 100 页、1,000 条记录和 8 MiB 解码数据；重复游标、超过上限或 schema 非法时显式失败，不把截断目录标为完整。stdio 使用 SDK 有界帧解码器，HTTP SSE 使用 SDK 事件大小限制，均为解码前 8 MiB；HTTP JSON 响应由 rmcp 解码后再检查结果大小，当前 SDK 不提供解码前体积限制接口。本期不复制 HTTP 传输实现，也不承诺隔离 SDK 解码时的内存耗尽。流式响应按消息和单次操作累计结果限制，不按订阅流的整个生命周期累计。一次完整工具目录刷新共享总操作期限，分页或重试不能重置期限。

资源与模板通过现有列表工具按需请求，转发远端分页游标并返回包含 data/next_cursor 的强类型页面，页面最多 1,000 条且受上述字节限制；读取操作使用当前连接，不依赖构造时缓存。保留已有可选 server 的聚合入口；聚合游标需记录服务位置和远端游标，按稳定服务顺序继续读取，每次只读取当前所需的有界页面。资源发现失败按操作错误表达，只在确认终止性传输失败时改变连接状态。

目录由现有注册表发布，连接任务写回使用本方案定义的代次校验。根据最新目录重新校验会话已激活的工具引用，不重写历史模型上下文。未知工具 annotations 不代表授权，不能将所有工具默认标为只读、非破坏性或可安全并行。沿用保守执行策略和现有权限检查，annotations 只辅助分类，不能授予权限。

端到端保留 `structuredContent`，包括新规范允许的非对象 JSON。工具描述符保留服务返回的输出 schema；模型工具声明沿用 Provider 的输入 schema 契约，不向其注入不支持的输出 schema 字段。内容类型通过现有模型/Provider 适配层传递。图片复用现有 FileService、附件读取和 Provider 编码能力，并补齐目前缺少的工具图片引用、模型输入和 UI 内容读取链路；图片字节不放进事件或普通 JSON 文本。音频或其他内容类型仅在现有链路能够端到端表达时接入；无法表示时返回强类型不支持内容错误，不得静默丢弃，也不得宣称完整多模态支持。

图片接线采用 `TalosContentItem::Image { fileId, mimeType, label }`；文件由现有 FileService 按调用者保存为个人文件，MCP 层不维护文件索引。现有 ToolContext 注入窄接口 `ToolImageStore`，应用适配已有上传和附件读取；不另建产物管理器。当前回合及用户操作续执行消息持久化文件 ID，续执行后按同一用户重新读取，二进制字段不序列化；已加载字节沿用当前回合的附件快照语义。普通历史压缩只保留图片引用说明，客户端仍能按文件 ID 读取。图片计入现有上下文预算，优先保留请求限制内最新的工具图片，超限图片在模型文本中明确标记省略。每张图片复用独立文件生命周期；工具取消或后续图片保存失败时，已完成的个人文件仍在文件管理中可见并可删除。Responses、Messages 和 Chat Completions 沿现有协议编码真实工具图片，并保留工具调用身份。模型输入能力由配置声明，Provider 校验支持的附件格式；不支持图片的模型明确拒绝，不能静默丢弃。DeepSeek 的 `deepseek-v4-flash-vision-exp` 已声明 `text/image`，原 Flash/Pro 保持纯文本。

客户端通过 `file/content`（请求复用 `FileReadRequest`）或 HTTP `GET /v1/files/{fileId}/content` 按所有者读取。`FileContentResponse` 返回文件元数据及传输用 `dataBase64`；SDK 转换为字节，UI 展示受鉴权读取的图片。该接口沿用 FileService 大小和状态校验，不接受存储路径或外部 URL。

注入模型前执行现有工具结果裁剪、产物存储及传输字节上限。单个注入项最多 10K tokens，具备明确来源和裁剪策略；新增可能超过 1K tokens 的内容项，按仓库当前规则完成额外人工审查。上下文回放遵守同一裁剪规则。

## 错误与兼容影响

遵循[统一错误契约](../../../docs/architecture/ERROR_MODEL.md)。内部失败状态保留原始 `TalosError` 和 SDK 强类型来源，快照及协议响应只暴露 `ApiError`。由错误码与结构化参数决定行为。远程操作拒绝、请求超时、不支持能力、鉴权失败和终止性传输错误不能全部触发服务关闭。

升级审查覆盖 app-server、HTTP/JSON-RPC、Rust/TS SDK、Plugin manifest、配置加载、原始事件、会话恢复以及 Web/Desktop/TUI 展示。实施导致公共类型变化时，由生成命令更新 schema。凭据刷新保持工具身份稳定。改变错误对象或工具目录行为时，补齐脱敏、协议和回放验证。

## 验收证据

离线集成测试通过内存传输执行真实客户端/服务端消息，不只比较静态类型。覆盖新规范发现、旧版协商、不支持版本、标量结构化结果、分页、重复游标、非法 schema、补充输入结果、取消、含 `is_error` 的完整结果、目录变化和故障隔离。使用确定性的本地 OAuth fixture 验证回调绑定、非法 state、刷新协调、过期、断开、账号替换、变更鉴权目标不继承旧凭据、断开后旧刷新/回调完成及服务间凭据不串用。这些测试不修改测试进程环境，也不依赖真实供应方。

真实 E2E 必须记录服务/软件包版本、传输方式、协商协议、鉴权方式、执行主机和观察到的结果。更新依赖或收到初始化响应，都不能单独作为兼容性证据。

| 样本 | 必须实际观察到的路径 |
| --- | --- |
| Playwright stdio | 导入官方命令配置，启动、发现、导航，通过强类型媒体链路消费截图，禁用后确认工具消失 |
| Context7 HTTP | 添加官方端点和凭据，发现并查询文档，确认凭据拒绝与传输失败分别表达 |
| GitHub 远程 HTTP | 按已配置客户端注册条件分别验证 PAT 与 OAuth，发现并执行只读操作，然后断开 |
| Notion 托管 MCP | 完成 OAuth，搜索授权内容，刷新/重连，断开，验证该服务不能继续使用已移除凭据，其他服务不受影响 |
| 健康与故障测试服务 | 同时启动，让其中一个崩溃或挂起，验证普通 Talos 操作和健康服务仍可用 |

供应方访问权限、OAuth 客户端注册和运行环境属于明确验收前提。缺少凭据时，相关 E2E 保持待验收，不能宣称整个功能已经验证。不得只为证明连接可用而修改外部账号数据。
