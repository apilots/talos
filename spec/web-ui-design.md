## 1. 设计背景与目标

### 1.1 产品定位

Talos Web UI 是 Talos AI 智能助理框架的 MVP 对外产品界面。目标用户是有一定技术背景的个人用户，期望一个干净、专注的 AI 工作伙伴，而非功能堆砌的平台产品。

### 1.2 设计原则

> 少即是多。用户打开产品，只想做一件事：和 AI 对话、完成任务。

| 原则 | 说明 |
|------|------|
| **简洁克制** | 不展示用户不需要的信息；每个页面只有一个主要焦点 |
| **对话优先** | 所有设计服务于"对话"这个核心动作，功能管理退居侧边 |
| **响应及时** | 流式输出、即时反馈，让用户感受到 AI 在实时工作 |
| **信息分层** | 主要内容突出，辅助信息轻描淡写，绝不喧宾夺主 |
| **暗色基调** | 深色主题，长时间使用不疲劳；参考 Linear、Raycast 的审美 |

### 1.3 参考产品分析

| 产品 | 借鉴点 | 避免点 |
|------|--------|--------|
| **ChatGPT** | 对话区宽度控制、消息气泡风格、左侧历史列表分组 | 功能入口过多、左栏视觉重 |
| **Claude.ai** | 侧边栏收缩/展开、文件上传入口克制 | 欢迎页信息过多 |
| **Linear** | 整体暗色风格、字体层次、图标极简 | — |
| **Raycast** | 快捷键驱动、搜索优先、交互响应快 | — |
| **Notion AI** | 内联工具调用展示风格、思考块折叠 | — |

#### 消息设计

**用户消息**：
- 右对齐，浅色圆角气泡（`#1E1E2E`）
- 用户首字母 Avatar 紧贴右侧
- 字体正常粗细，无装饰符号

**AI 消息**：
- 左对齐，无气泡背景（内容直接渲染在页面上，减少视觉框架）
- Talos 六边形小图标 `⬡` 在左侧
- Markdown 完整渲染：标题/粗体/斜体/列表/表格/代码块
- 代码块右上角浮现复制按钮

## 4. 交互细节

### 4.1 侧边栏行为

- 默认 260px 展开状态
- 窗口宽度 < 1024px 时自动折叠为 56px 图标模式
- 移动端（< 768px）为抽屉式覆盖层
- 历史会话 hover 时右侧出现 `···` 操作菜单（重命名 / 删除 / 分享）
- 会话标题取首条用户消息前 40 字，自动生成
- `⌘K` 全局搜索历史对话

**会话分组规则**（同 ChatGPT）：
- 今天
- 昨天
- 过去 7 天
- 过去 30 天
- 更早（按月分组）

### 4.2 快捷键

| 快捷键 | 功能 |
|--------|------|
| `⌘K` | 打开全局搜索/命令面板 |
| `⌘N` | 新建对话 |
| `⌘↵` | 发送消息 |
| `⌘/` | 聚焦输入框 |
| `Esc` | 停止 AI 生成 |
| `⌘Shift+C` | 复制最后一条 AI 回复 |
| `⌘[` | 切换到上一个会话 |
| `⌘]` | 切换到下一个会话 |

### 4.3 消息操作菜单

鼠标 hover 到任意消息时，消息底部浮现操作行：

AI 消息：
```
                            [👍] [👎] [📋 复制] [🔄 重新生成]
```

用户消息：
```
                            [📋 复制] [✏️ 编辑]
```

编辑用户消息后，从该条消息重新生成（删除之后的历史）。

### 4.4 命令面板（`⌘K`）

受 Linear / Raycast 启发，提供统一的命令/搜索入口：

```
┌──────────────────────────────────────────────────────┐
│  🔍  搜索或输入命令...                                │
├──────────────────────────────────────────────────────┤
│  最近会话                                             │

│  💬  帮我写一个 Rust 迭代器          今天 10:18        │
│  ─────────────────────────────────────────────────    │
│  操作                                                 │
│  ＋  新建对话                                          │
```

### 5.4 动效原则

- 有意义才动：只在传递状态变化信息时使用动画
- 快速响应：交互反馈 < 100ms（视觉，非网络）
- 不炫技：拒绝页面入场动画、复杂粒子效果
- 侧边栏展开/收起：`200ms ease-out`
- 弹窗出现：`150ms ease-out` 轻微缩放
- 流式文字：直接 append DOM，无淡入动画（频率太高会卡顿）

## 6. 响应式设计

### 6.1 断点规则

| 断点 | 宽度范围 | 侧边栏 | 对话区宽度 |
|------|---------|--------|-----------|
| 宽屏桌面 | ≥ 1440px | 260px 展开 | 最大 768px 居中 |
| 标准桌面 | 1024–1439px | 260px 展开 | 自适应（留边距） |
| 平板横屏 | 768–1023px | 56px 图标模式 | 全宽（去侧边栏宽度） |
| 移动端 | < 768px | 抽屉覆盖 | 全宽 |

### 6.2 移动端特殊处理

- 输入框固定在底部，与软键盘高度协调（用 `viewport-fit=cover`）
- 工具调用卡片默认折叠（屏幕宽度有限）
- 消息操作通过长按触发（替代 hover）
- 侧边栏通过左滑手势或汉堡菜单打开

### 7.1 与 Talos Gateway API 对接

现有 API 可直接复用：

```typescript
// 创建会话
POST /v1/sessions
{ context: { source_type: "web", provider: "web", user_id: "...", ... }, model: "qwen-plus" }
```

```typescript
POST   /v1/files                     // 上传文件（multipart/form-data）

```

## 8. MVP 范围界定

### ✅ MVP 包含

- **Chat 页面**：完整对话、工具调用展示、流式响应、思考过程折叠
- **工具审批**：内联确认卡片，调用 tool-approvals API
- **会话历史**：左侧列表、分组（今天/昨天/过去7天）
- **Memory 页面**：查看记忆、删除记忆（手动添加为可选）
- **Files 页面**：上传文件、列表展示、删除、`@` 引用
- **Settings 页面**：API Key 配置、默认模型选择、工具权限开关
- **暗色主题**（唯一主题，不做浅色主题切换，MVP 阶段聚焦）
- **响应式适配**（桌面 + 平板，移动端尽力而为）

### ❌ MVP 不包含

- 多用户账户系统 / 团队协作
- 移动端原生 App（Web 响应式已覆盖）
- 插件/扩展市场
- 语音输入/输出
- 浅色主题
- 会话导出（PDF/Markdown）
- 高级搜索（全文检索历史消息）
- 实时协作（多人同时编辑）

## 9. 设计理念总结

Talos Web UI 的核心设计信念是：**一个好的 AI 工作界面，应该让用户忘记界面本身的存在**。

具体体现在三个层次：

1. **视觉层**：极深背景、克制的品牌色用量、对话区宽度限制——让眼睛聚焦在对话内容，而非 UI 框架。

2. **交互层**：流式输出不打断阅读、工具调用折叠不干扰正文、快捷键体系覆盖高频操作——减少操作成本，让用户停留在"心流"状态。

3. **功能层**：Memory 和 Files 是支撑工具，不是主角——它们存在的意义是让对话更有上下文、更有延续性，而不是制造新的管理负担。
